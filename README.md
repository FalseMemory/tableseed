# tableseed

> 多表联合造数工具 —— 跨表一致的测试数据生成器

给一组表和它们之间的关联关系，产出**可以直接入库、且跨表对得上账**的测试数据。

```
表结构 + 关联关系 + 业务规则   ──►   tableseed   ──►   SQL / CSV / 直连入库
```

## 它要解决什么

单表随机造数很容易，难的是**多表联动**：

| 痛点 | 具体表现 |
| --- | --- |
| 关联断裂 | 流水表的 `account_no` 在主表里查不到，外键直接炸 |
| 口径不符 | 明细汇总与余额表对不上，数据核对场景无法用 |
| 脚本散落 | 每个需求各写一套 INSERT，无法复用、无法版本化 |
| 不可复现 | 随机造数每次结果不同，缺陷无法稳定重现 |
| 状态跳跃 | 造出"已销户却仍有在途交易"这类业务上不可能存在的组合 |

## 核心能力（设计目标）

1. **元数据自动扫描** —— 读表结构，识别主键、唯一约束、非空、外键、字段类型与长度。
2. **关联关系声明** —— 用 YAML 描述 1:1 / 1:N / N:M 关系；生成顺序由依赖拓扑排序自动推导，父表先于子表。
3. **字段级规则引擎** —— 枚举、区间、正则、字典、序列、引用其他表字段、表达式派生。
4. **多表一致性** —— 业务主键在关联表之间传播，保证上下游口径一致（对账场景可用）。
5. **状态机造数** —— 按业务生命周期生成链式数据，例如 `开户 → 交易 → 结息 → 调息`，避免非法状态组合。
6. **可复现** —— 固定随机种子，同样的配置永远产出同样的数据。
7. **多出口** —— 输出 SQL 脚本 / CSV 文件 / 直连数据库批量入库。

## 配置样例（草案）

```yaml
tables:
  customer:
    rows: 1000
    fields:
      cust_no:   { type: seq,  prefix: "C", width: 10 }
      cust_name: { type: dict, source: names }
      open_date: { type: date, range: [2020-01-01, 2026-09-01] }

  account:
    rows: 3000
    fields:
      acct_no: { type: seq, prefix: "ACC", width: 16 }
      cust_no: { type: ref, table: customer, field: cust_no }   # 外键联动
      balance: { type: decimal, range: [0, 1000000], scale: 2 }

relations:
  - from: customer.cust_no
    to:   account.cust_no
    kind: 1:N

seed: 20260910   # 固定种子，结果可复现
```
